# 位置矫正节点实施计划

日期：2026-10-19。依据代码基线 `120e294` 制定；以下保留原计划和验收目标。**同日已完成首版实现**，实际范围以 [使用说明](POSITION_CORRECTION_NODE.md) 与 [检查记录](evidence/2026-10-19-position-correction.md) 为准。核心/生命周期最终 518 项、匹配回归 197 项、布局 113 项通过；真实产品为有限链路检查，长期现场及完整精度未验收。

## 1. 目标与首版范围

产品在相机下发生平移或旋转时，利用快捷匹配获得的当前位姿，将本轮图像变换到示教图像的基准位置。下游在矫正图上使用固定 ROI，优先打通已有 P1～P6 检测流程。

```text
读取图像 / 相机 ── Image ─────────────────┐
       └── Image → 快捷匹配 ── Poses ────┤
                                        ▼
                                    位置矫正
                                        │ 矫正图像
                         ┌──────────────┼──────────────┐
                         ▼              ▼              ▼
                       分类检测       目标检测        直线查找
                         └── 在基准图上配置固定 ROI ────┘
```

两条输入使用同一轮、同一帧、同一输入坐标空间。原图保留；输出为新的图像对象。匹配节点的彩色 preview 含人工绘制轮廓，不能作为待矫正的算法原图。

首版：单个产品、一个有效匹配、二维刚性平移及旋转、固定基准画布、文件夹逐张和相机逐帧。多检测 ROI 由现有下游节点承担。原生图像元组输入首版显式拒绝，不能默认选第一张；文件夹正常逐轮运行。

后续阶段：原图上的 ROI 跟随、多目标逐件矫正、缩放/透视、标定及机器人坐标。首版不将这些能力混在同一节点中。

## 2. 当前代码需要补齐的接缝

| 现状 | 实施要求 |
| --- | --- |

## 3. 用户操作与基准示教

1. 在良品或合适的标准图片上完成快捷匹配的模板和搜索范围配置，确保只找到一个目标。
2. 添加位置矫正节点，接入原始 Image 和快捷匹配 Poses。
3. 在节点属性点击一次图标“设为基准”。停止运行后校验最后一次有效结果与当前配置是否一致；没有可用结果时提示先单次运行，不隐式改写基准。
4. 保存参考行、列、角度、画布宽高、匹配节点 ID、模型身份、上游配置签名及示教时间。基准必须来自本轮匹配结果，不能靠鼠标点选猜测模型原点。
5. 单次运行，选择位置矫正节点查看真实矫正图。下游 P1～P6 在这幅基准坐标图上重新确认 ROI。
6. 保存项目，再用有偏移和旋转的图片验证；生产连续运行期间基准保持不变。

换模板内容、模板 ROI、建模参数或匹配输入源后，原基准标为失效，需重新示教。切换输入尺寸时显式报错，不自动缩放；同尺寸更换物理相机/视野也应人工重新示教，软件不能仅凭尺寸判断等价。修改搜索范围和评分不改变模型坐标原点，但示教动作仍需验证当前结果未过期。

“设为基准”“清除基准”仅在节点属性各保留一个图标入口；鼠标停留 1.5 秒显示中文说明。参考坐标和状态保留文字，参数不放进检测模式。示教信息使用可换行区域，避免挤走操作按钮。

## 4. 输入输出契约

拟定节点：`halcon.position-correction`，显示名称“位置矫正”，分类“定位匹配”。

### 输入

| 端口 | 类型 | 约束 |
| --- | --- | --- |
| image | halcon.image | 本轮单幅未绘制标注的图像 |
| poses | vision.pose-set | 同帧快捷匹配输出；必须只有一个有效位姿 |

先为快捷匹配增加 poses 端口，原有 matches、imageResults 和数值端口保持兼容。`PoseSet` 至少包含 SourceFrame、ModelIdentity、Matches。ModelIdentity 为模板内容和建模设置摘要；不使用路径或文件修改时间代替内容身份。

`FrameReference` 至少包含 RunId、ImageIndex、生产图像的 NodeId/PortId、Width/Height、SpaceId。引擎构建每个图像端口的元数据并向下游传播；大小不变的几何变换仍生成新的 SpaceId。运行标识不保存为下次可复用的帧。仅连 JSON 常量或重放旧位姿不能通过同帧校验。

### 输出

| 端口 | 类型 | 含义 |
| --- | --- | --- |
| image | halcon.image | 基准尺寸的矫正图，同时用作节点图像显示；避免增加重复 preview 端口 |
| transform | vision.transform2d | 当前→基准、基准→当前矩阵及两端坐标身份 |
| offsets | object | 本轮位姿、基准位姿、行列差、归一化角度差及评分 |
| validRegion | halcon.region | 矫正图中来自有效输入像素的区域 |
| status | inspection.result | 正常完成时 CORRECTION_OK；失败走执行错误通道，无替代图像 |

参考坐标和全部矩阵保留精度，显示可适当舍入。行列差定义为“当前减基准”，便于诊断；它不等于同时存在旋转时矩阵中的平移分量，必须分开命名。角度输出用度，HALCON 调用时转换为弧度。

## 5. HALCON 算法和坐标约定

从当前位姿到基准位姿构建刚性变换，矩阵求逆提供反向映射。HALCON 官方说明 `vector_angle_to_rigid` 可按参数顺序构建这两个方向。[官方算子说明](https://www.mvtec.com/doc/halcon/2411/en/vector_angle_to_rigid.html)

平台规范使用像素中心的行列坐标，标准矩阵 `M` 满足：当前参考点经 M 映射到基准参考点。固定记录方向及行列约定，禁止在显示代码中临时交换 x/y 或反转角度。

图像重采样采用 `affine_trans_image_size`，输出为示教宽高，默认 bilinear。该算子忽略输入 domain，并使用像素角点坐标；应按官方约定将标准矩阵适配为 `Mimage = T(+0.5,+0.5) · M · T(-0.5,-0.5)`，集中封装并通过独立基准验证。[固定画布与坐标注意事项](https://www.mvtec.com/doc/halcon/2411/en/affine_trans_image_size.html)

标准几何点按 M 变换；若使用 `affine_trans_pixel`，应使用对应适配矩阵，确保与图像一致，不能重复半像素补偿。矩阵序列化同时保存坐标约定标识，显示层不得直接猜测矩阵用途。[像素坐标变换](https://www.mvtec.com/doc/halcon/2411/en/affine_trans_pixel.html)

实施前以本机 24.11.1.1 随附文档及真实调用复核；在线文档当前为 24.11.3.0，不能据此宣称本机 API 已验证。

### 有效区域与边界

- 将输入真实 domain 同步变换并与基准画布求交，生成 validRegion；图像角落补黑不能当作缺陷证据。
- 下游矩形 ROI 必须完全位于有效区域。为分类、分割、目标检测和直线查找增加公共覆盖检查；区域不完整时明确报错，首版不静默裁小、不把黑角送入推理。
- 全图检测同样检查覆盖；存在无效角落时需改为有效范围内的 ROI。二值化保留有效 domain，Blob 随输入区域处理。
- 保持像素类型和通道数；首版明确支持 byte 的单通道/RGB，其他类型给出错误，不悄悄归一化或转 byte。后续再增加经过验收的类型。

## 6. 失败、选择与运行行为

| 条件 | 预期行为 |
| --- | --- |
| 尚未示教 / 基准失效 | REFERENCE_REQUIRED / REFERENCE_STALE；无矫正输出 |
| 未找到匹配 | POSE_NOT_FOUND；无图像/矩阵，不沿用上一轮 |
| 多个匹配 | POSE_AMBIGUOUS；首版要求唯一匹配，不自动按返回顺序选产品 |
| 图像和位姿来源不同 / 帧不一致 | FRAME_MISMATCH；即使尺寸相同也拒绝 |
| 尺寸、类型不支持 / 非有限位姿 | SIZE_MISMATCH / IMAGE_TYPE_UNSUPPORTED / POSE_INVALID |
| 用户启用的最大位移或角度限制超出 | POSE_OUT_OF_RANGE；限制值保存在节点属性 |
| 取消 / native 异常 | 退出本轮并释放临时对象，下游不继续使用旧数据 |

首版可选限制默认未启用，启用后才要求阈值；角度差规范化到 `[-180°,180°)`，用跨 ±180° 的样本验收。多目标选择策略留到后续明确定义，不增加默认“最高分”以掩盖歧义。

节点读取输入对象不接管上游所有权。临时 HImage/HRegion/HTuple 在异常和取消路径释放；输出交给 WorkflowExecutionRun 集中释放。变换数据为受管数值，无跨轮 native 句柄；不增加模型缓存。单次和连续共用执行器，停止等待当前同步算子返回，不能承诺立即打断 native 算子。

## 7. 图像与结果显示

首版发布要求：在**矫正图**上组合分类、目标检测、直线等下游结果，所有坐标属于基准空间。采集原图和矫正图可在现有显示配置中分别选作底图，复用现有面板和缩放平移交互，不新建重复视图工具栏。

SpaceId 不同时，首版阻止直接叠加并提示原因；不得以共同采集源或相同尺寸判定可混用。原图上的快捷匹配轮廓仍显示在原图，基准空间的检测框显示在矫正图。

后续完整回投再使用逆矩阵：矩形四角变成四边形，不能只变换左上和右下；轮廓逐点映射，掩膜用最近邻，线段端点与方向共同变换。双向矩阵首版就输出，为回投和后续计算保留接口；**自动把所有下游结果回投到原图不是首版完成条件**。

## 9. 验收标准

以下为原定验收目标；已执行部分及未覆盖项见检查记录，不能把本清单直接视为全部通过。

1. **几何基准**：独立生成已知平移、正负旋转、90° 和跨 ±180° 图像；点的正反变换误差 < 1e-6 像素，图像标志点对齐误差 ≤ 1 像素。包含纯平移、恒等变换和非整数中心，避免同一错误公式生成和验证。
2. **固定 ROI 链路**：标准图绘制 P1～P6，偏移图经“读取→匹配→矫正→检测”后仍定位相同物理区域；原图保留，矫正后尺寸固定。用独立产品样本检查插值对分类/分割/目标检测的影响，不承诺结果绝对不变。
3. **错误传播**：无基准、换模板、零/多匹配、非有限数值、错图同尺寸、旧帧、尺寸变化、原生多图输入、超限、边缘缺失逐项验证；下一轮不得残留上一轮图像或矩阵。
4. **有效区域**：大角度旋转产生黑角；覆盖不足的任何启用 ROI 在推理前报错，完全有效的多个 ROI 正常运行。
5. **持久化**：示教参数、节点连线、ROI、空间配置保存重启一致；复制和导入后的引用正确；损坏/缺少基准被准确拦截。检查仅使用副本。
6. **显示与 UI**：编辑/检测模式、模板和矫正图选择、长信息、面板调整、常用/最小尺寸、1500ms提示和入口去重；实际运行截图按项目规则交付。
7. **生命周期**：至少200轮正/负样本交替，20次启停，执行中停止、项目切换和关闭；记录内存趋势及所有输出对象释放，无未初始化旧对象访问。有限轮次不替代产线长时间验收。
8. **回归**：快捷匹配197项、布局检查、既有HALCON算子/显示/ROI相关检查，以及真实模型的有限链路复测。按最终代码重新统计结果，不照抄旧通过数。
