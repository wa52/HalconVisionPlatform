# 多 ROI 裁剪推理与分类检测

更新：2026-10-16。语义分割与分类的多 ROI 已通过真实差分推理与 100 轮缓存回归；已检查实际绘制、保存及缩放，完整编辑矩阵和长期稳定性仍待验收。见 [实测记录](evidence/dl-roi-validation-20261016.md)。下文早期单 ROI 说明保留历史背景，由本节补充。

## 多 ROI 流程与结果约定

1. 原图输入 → 校验 ROI 列表及设备参数 → 通过工作区缓存获取模型会话；首次或模型包元数据变化时完整校验模型包。
2. 按列表顺序遍历启用的 ROI：裁剪 → 官方预处理 → 推理 → 解析各自结果。会话供本轮与后续轮次复用，停止/切换/关闭清理；独立执行器未传缓存时仍逐轮加载释放。见 [缓存所有权](DL_SESSION_LIFECYCLE.md)。
3. 分割标签最近邻还原到每个 ROI 的原始尺寸，再映射回原图坐标；所有框外像素不参与统计。每个 ROI 保留独立掩膜，不进行相互覆盖或投票合并。
4. 分类返回每个 ROI 的 Top-1、置信度、全部类别评分和低置信度状态；预览保留原图。检测模式可在同一原图上组合多个节点的 ROI 框、名称及结果标注。
5. 临时资源清理并归还会话租约后，才把输出交给当前 WorkflowExecutionRun。任意 ROI 出错则该节点失败，错误带 ROI 名称，回收该会话和已产生的部分输出；取消在原生算子前后检查，不能强行中断 HALCON 原生调用。

## 编辑与保存

选中语义分割或分类节点，在“多 ROI 检测范围”中点击“新增 ROI”，到节点图像区拖动绘制矩形，松开完成；Esc 取消。列表可修改名称、启用/禁用，支持重绘选中、删除选中和清空。框和名称跟随图像缩放、平移。运行时先停止再绘制。保存项目后恢复 ID、名称、范围、启用状态。

- 每个节点最多 64 个 ROI，名称和 ID 不重复。
- 空列表表示全图；非空列表全部禁用时明确报错，不擅自退回全图。
- 非有限坐标、完全越界和小于 2×2 像素的范围报错；部分越界裁到图像边界，反向绘制自动归一化。
- 旧项目只有 `roi` 字符串时仍按原单 ROI 执行；编辑后写入 `rois` 列表，新列表优先。旧项目不因打开而自动改写文件。
- 无效名称或列表编辑会阻止保存、导出及运行，避免界面与实际执行参数不一致。

## 下游数据

| 输出 | 多 ROI 语义 |
| --- | --- |
| `roiResults` | 按启用 ROI 的列表顺序输出，含 RoiId、RoiName、Bounds、Status、InferenceMilliseconds，以及分类或分割明细 |
| 分类 `classId/className/confidence/scores/roi` | 单 ROI 保持兼容；多 ROI 标量及 roi 为 null，scores 为空数组，使用 roiResults 读取各区域结果 |
| 分割 `objects` | 每个对象带 RoiId/RoiName、原图坐标及面积 |
| 分割 `count/area/classes` | 对各 ROI 独立结果累计；重叠部分可能重复计数，占比之和可能大于 1，不表示去重后的整图占比 |
| 分割 `mask` | HALCON HImage 对象元组，每个 ROI 一张原图尺寸、仅 ROI 有效域的标签图；元数据 count/roiIds/validRois 与元组顺序对应，单 ROI 另保留 validRoi |

检测模式选择分割节点的 `mask` 端口后，可通过新增的 ROI 下拉框切换不同掩膜，选择随项目保存。输出参数/检测结果可展开 `roiResults`，选中数组行复制完整 JSON。预览中的绿色为筛选后目标区域，黄色为检测范围；分类结果不自动解释为产品 OK/NG。

本轮实际验证了裁剪执行一致性、映射边界、保存恢复及 100 轮资源行为；尚未给出产品精度、长时间显存曲线和现场稳定性结论。

## 早期单 ROI 实现前流程分析（历史记录）

两个深度学习节点共用矩形裁剪约定：ROI 参数存原图行列坐标，端点可反向绘制，越界部分裁到图像边界；完全越界、非有限数和不足 2×2 像素的范围报错。未设置时使用全图。先 CropRectangle1，再使用对应模型目录的官方预处理参数推理，不通过 ReduceDomain 假装裁剪输入。

语义分割将模型标签最近邻还原到 ROI 大小，再平移放回原图大小的掩膜，并限制掩膜有效域为 ROI，避免框外背景参与类别统计。区域、中心、外接矩形天然回到原图坐标。面积和坐标单位仍为原图像素，占比仍以原图总像素为分母。输出 roi 记录有效范围；导出掩膜时还需保留此范围，框外不是有效预测。

分类模型读取 HalconTrainingPlatform 的 ClassificationPipeline：model.hdl、preprocess.hdict、manifest.json 和可选类别/校验文件；调用 preprocess_dl_samples，再读取 classification_class_ids、classification_class_names、classification_confidences。校验实际模型类别映射，输出 Top-1 类别、置信度及所有类别评分；低于配置阈值标记 LOW_CONFIDENCE，不伪造识别结果，也不由类别名称前缀推断产品 OK/NG。

本机已找到最新完成评估的分类模型 run_20261015_204851_6dfa373c（256×256，10 类）。准备的 artifacts/dl-roi-classification/NH320_分割与分类ROI.hvproj 同时绑定该分类模型和最新分割模型，ROI 初始为空，需用户按检测场景绘制；原有项目未改动。模型路径只写入本机项目文件，程序不硬编码机器路径。

分类预览保留原图，并显示 ROI；分类文字通过统一检测面板叠加。所有输出和 ROI 参数随项目保存，沿用文件夹/相机运行链路。两个节点每次执行独立拥有模型和临时资源，成功清理模型后才把输出交给 WorkflowExecutionRun；取消无法抢占原生算子。

ROI 裁剪改变输入内容和缩放比例，实际效果需要样品确认，不能保证与全图结果一致。上述早期实现最初仅完成编译，后续真实多 ROI 与分类检查已记录在本文开头及验收文档中。
