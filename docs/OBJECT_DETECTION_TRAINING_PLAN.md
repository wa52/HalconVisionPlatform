## 1. 目标与第一版范围

首先形成“现有 HALCON 检测模型及训练预处理 → 加载核对 → 原图推理 → 节点接入 → 结果及判定”的链路。需要继续训练时，再执行“人工确认的检测框 → 独立划分 → HALCON 训练 → 独立评估 → 模型包更新”。

第一版沿用 HALCON 24.11、.NET 8、WPF。采用水平矩形框 `rectangle1`；支持全图和多个矩形 ROI、文件夹回放、单次/连续/停止。训练留在 HalconTrainingPlatform，推理与交互留在 HalconVisionPlatform。

训练平台现已区分单类别预标注模型与最终合并模型：各文件夹独立审核/预标注，最终将所有已确认类别合并为一份 `.hdict`，训练一个多类别 HALCON 检测器。节点选择这个合并模型，在 P1～P6 六个 ROI 中分别查找对应类别；多 ROI 共用同一模型。

本次使用合并模型 `run_20261018_222050_5a0b4207`，复用此前 P1～P6 的原始 ROI。矩形旋转框、实例掩膜及多模型自动调度不纳入这一版。

### 现有 HALCON 模型接入安排

- 使用现有 `.hdl` 和与其训练一致的 `preprocess.hdict`，读取任务类型、框类型、类别、输入尺寸和通道，先做真实原图推理核对。

## 3. 数据与标签计划

### 3.1 明确检测对象

先为每个位置写明：目标实物、允许位置范围、正常数量、可框选的缺陷类别、空图含义。缺料位置没有实物时，不凭空画一个“缺失物体框”；用“必需目标数量不足”判定缺失。若要识别缺损外观或空位区域，必须定义可重复标注的可见对象，必要时沿用分类节点进行外观判定。

原有 P1～P6 `.hobj` 是搜索范围，不自动成为目标真值框；分类目录名也不是完整检测框标签。检测框应包住实际目标，逐张确认，原图及原有标签只读。

### 3.2 采集与审核

1. 先复核已有人工确认框及类别映射，再用已有模型生成待审核候选；人工补漏框、删误框、修类别与边界。
2. 每个普通目标类别，首轮采集预算为 100～300 张不同工件正样本，加 50～100 张人工确认的无该目标/易混背景。每种 NG 外观尽可能覆盖不同真实缺陷工件；数量不足单独列为证据缺口，不用复制或增强凑独立样本。
3. 上述数量只是采集起点，不是精度保证；以学习曲线、错误分布和独立测试结果决定继续补样。
4. 覆盖照明、反光、位移、旋转、尺度、遮挡、批次差异；优先补漏检、误报和相似背景。
5. 记录原图 ID、工件/批次、ROI 来源、标注人、审核状态和图像哈希；模型预标注未审核不得自动加入真值。
6. 单类别预标注各自达到启动门槛；最终合并模型只收集 approved 图像与真实框，保持类别 ID，不收集待审、草稿或需重标图像，不覆盖预标注模型。

### 3.3 防止数据泄漏

- 先按真实工件/批次分组，再按组约 70%/15%/15% 划分 Train/Val/Test；比例为建议，按组和类别覆盖调整。
- 同一原图的 P1～P6 裁图、同工件连拍、增强版本、重复文件不得跨集合。各独立模型共用一致的工件划分清单。
- 增强只作用训练集。验证集用于选模型及阈值，测试集封存，最终评估一次；持续用于补样的数据退出封存测试集。
- 现有 267 张原图及其训练裁图不能直接认定为独立测试集。若缺少新工件/新批次，标记“链路验证”，不输出泛化准确率结论。
- 每个集合统计正样本、确认负样本、类别/框数量和组数；某类测试缺失时，明确该类未验收。

## 4. 训练实施

### A. 环境与 HALCON 冒烟关卡

在独立 Worker 中检查实际 HALCON DLL/运行库、GPU、预训练 backbone、模型类型和预处理。运行“建模 → 一个 batch 训练 → 保存 → 重新加载 → 真图推理”，记录完整错误、版本和资源退出。

已有模型接入先执行“加载 → 检查模型/预处理 → 真图推理 → 释放资源”；上面的训练冒烟仅在确需继续训练时执行。不能从分类推理成功或 GPU 枚举成功推断目标检测训练成功。在线官方 24.11 文档当前显示 24.11.3，本机此前验证为 24.11.1.1；关键算子仍以现场验证为准。失败即记录阻塞原因，不修改 HALCON 安装或授权机制。

### B. 参数和对照实验

| 项目 | 初始安排 | 调整依据 |
| --- | --- | --- |
| 框类型 | rectangle1 | 先覆盖水平框需求 |
| 输入 | 首先验证现有 HALCON 512×512；正式对照 512 与 640 | 目标缩小后的像素大小、召回、显存和端到端耗时 |
| Batch | 1 起步，显存允许再试 2/4 | 每次记录峰值显存和失败原因 |
| 学习率 | 继续训练优先核对原训练参数；新实验可从 HALCON 入口 0.0001 起步 | 用验证曲线决定降低/调整 |
| Epoch | 5 轮仅作冒烟；正式预算 40～100 轮 | 保存验证最优模型；早停与耐心值在正式训练器补齐 |
| 增强 | 依据真实变化设置小位移、亮度、合理角度 | 图像与框同步变换；不做违背工件结构的翻转/变形 |
| 并发 | 单 GPU 首先串行 | HALCON 并发训练另验 |
| 阈值 | 验证集选置信度及 NMS 条件 | 按类别召回、误报与数量规则选择；0.05 预标注阈值不直接用于部署 |

这些参数是可编辑的试验起点，不承诺最佳精度或训练耗时。小目标若在全图缩放后信息不足，优先对照固定搜索 ROI 裁图训练；训练裁图策略必须与节点运行一致，并记录坐标变换。

### C. 正式训练器需补齐

- 新版已按类别分层进行 70/15/15 图像级划分，优化器只使用 Train；仍需按真实工件分组防泄漏、逐轮验证指标及实际轮次记录。
- 使用 HALCON 检测流程建模/预处理和训练；验证可采用 `evaluate_dl_model`，启用详细评估输出 TP/FP/FN。
- 按预先确定的验证指标保存 best，同时保留 last、参数、随机种子、backbone 哈希、数据快照哈希和日志；失败/取消不得登记为验证通过。
- 训练图像/字典/tuple 按批释放；模型和设备归 Worker 所有。停止先协作取消，原生调用返回后清理；不安全或无法及时取消时使用 Worker 进程边界，不在 UI 线程强行清句柄。

## 5. 独立评估与模型准入

报告 mAP@0.5、mAP@[0.5:0.95]、逐类 Precision/Recall、TP/FP/FN、负样本误报、每位置漏检及正常数量判定错误。明确 IoU、一对一框匹配、置信度和 NMS 设置；多框不能重复匹配一个真值。

试点候选门槛：mAP@0.5 ≥ 0.95、普通必需目标 Recall ≥ 0.99、已定义 NG 外观 Recall ≥ 0.99、正常工件误报率 ≤ 1%。这是待按现场漏检成本确认的工程目标，不是当前成绩，也不是普适生产标准。报告样本量及置信区间；极少样本的“零漏检”不能证明达到 99% 召回。

每次附漏检、误报、重框、错类和定位错误清单。测试不达标回到训练/验证补样阶段，保留测试集冻结和版本审计；不能通过反复调测试集阈值获取通过结论。

模型包计划：

```text
models/detection/<类别>/run_<版本>/
  model.hdl
  preprocess.hdict
  manifest.json
  classes.json
  checksums.json
  split.json
  training_params.json
  validation_report.json
  test_report.json
```

manifest 明确 `schemaVersion`、`task=detection`、`backend=halcon`、`instanceType=rectangle1`、`classIds/classNames`、HALCON/设备信息、模型/数据/预处理版本和验证状态。输入尺寸、通道、normalization、domain_handling 从真实模型/预处理读取并核对。沿用目前 full_domain 支持范围，拒绝不支持的预处理。

部署核心为模型、预处理、类别及校验元数据；报告用于追溯。导出前重新加载模型并复跑固定样本，校验文件哈希。保留 `bootstrap_unvalidated`，新增经过验证的状态约定；未验证包只用于明确标记的调试，不自动转成生产模型。

## 6. 目标检测节点接入设计

计划新增 `halcon.object-detection`，复用工作区模型缓存、运行输出所有权、多 ROI 编辑和检测面板。

| 类别 | 内容 |
| --- | --- |
| 输入 | Image |
| 参数 | 模型包、设备、多 ROI、目标类别、置信度、NMS 条件、最大检测数、期望数量、正常/NG 类别角色 |
| 输出 | objects、count、roiResults、decision、status、preview、overlay、modelInfo |
| 单个目标 | ID、类别 ID/名称、置信度、原图坐标框、中心点、宽高、来源 ROI；不返回虚构对象 |
| 单个 ROI | 搜索框、有效目标列表、过滤原因、目标数量、判定和耗时 |

执行顺序：验证包 → 取得缓存独占租约 → ROI 裁剪/预处理 → apply_dl_model → 解码框与类别 → 逆变换至原图 → 阈值/NMS/数量判定 → 托管显示快照与结构化输出 → 释放临时资源。

### 坐标与缓存要求

- 只接受实际 `type=detection`、`instance_type=rectangle1`，核对模型与清单的类别 ID/名称映射，不将任意类别 ID 当数组下标。
- 保存缩放、裁剪、padding 的完整变换；反变换包括 ROI 原点，核对像素中心/边界约定，不直接复制未经验证的简单宽高比例算法。
- 本次实现保留各 ROI 独立结果，count 是逐 ROI 接受目标数之和，重叠 ROI 可能重复计数，modelInfo 明确该口径；跨 ROI 全局去重后续单列，不能将当前 count 当成全图唯一物体数。
- 同一模型缓存用于多个节点时，置信度/NMS 等可变模型参数必须在独占租约内逐次显式设置，不能残留上一个节点的设置。
- 本轮空结果返回 `objects=[]、count=0`，显示当前搜索框及未检出标记，不沿用上轮框；错误、取消、未运行保留独立状态。
- 不向序列化数据或显示层泄漏 HImage、HDict、HDlModel 等句柄；重跑释放旧输出，停止/切换模型或项目/关闭时等待在途租约后清理缓存。

### 三色规则

| 情况 | 显示与判定 |
| --- | --- |
| 检出正常目标，满足类别及数量条件 | 绿色 OK |
| 必需目标缺失、数量不符或候选均低于阈值 | 搜索 ROI 红色 NG · 未检出/数量异常 |
| 实际检出已定义 NG 类目标 | 缺陷目标框蓝色 · 检出 NG |
| 模型/设备/图像/运行错误 | 独立 ERROR，不显示 OK、不复用旧结果 |

当前节点用可配置 NG 前缀映射缺陷类，`expectedClass=$roi` 时按 ROI 名称筛选正常目标；候选框和被接受框分别保留。仅训练普通类的模型不能凭空输出 NG 类；仅训练缺陷的模型“未发现缺陷”也不能自动证明正常目标存在。后续加入 NG 类后需重新评估正常与缺陷冲突时的组合规则。

## 7. 实施顺序与交付关卡

| 顺序 | 工作 | 可复查交付物 / 进入下一步条件 |
| --- | --- | --- |
| 1 | 定位现有 HALCON 模型与训练预处理 | 实际文件、type/instance_type、类别和输入参数；加载及单图推理记录 |
| 2 | 接入一个目标检测节点 | 单图实际框、原图坐标与训练程序结果对照一致 |
| 3 | 多 ROI、数量判定及三色显示 | 边界/重叠/空结果/错类/低分场景、保存重开、单次/连续/停止验收 |
| 4 | 独立评估现有模型 | 指标、样本量、错例与阈值记录；不足时明确补样和训练需求 |
| 5 | 按需补样、审核与分组划分 | 不可变 COCO 与 split、各集合样本统计和泄漏检查记录 |
| 6 | 按需完善正式训练/验证/最佳模型导出 | loss 与验证曲线、best/last、模型包、重载结果及冻结测试报告 |
| 7 | 资源与其他位置推广 | 100 轮回归，再 1 小时稳定性采样；各位置分别通过独立评估和节点验收 |

生命周期检查记录首次加载/预热与稳定推理分别耗时、端到端 P50/P95、停止响应、进程内存、GPU 显存与缓存条目。反复启停、切换模型/项目、异常失败、关闭都要验收；不要求显卡驱动显存立刻归零，以原生对象释放、缓存状态、稳定趋势和 Worker 退出综合判断。1 小时检查不是长时间产线验收，实际节拍目标需按现场要求确定。

本轮使用现有模型做节点实现与测试，不重新训练。独立精度、训练优化和生产验收仍按关卡逐项推进。
