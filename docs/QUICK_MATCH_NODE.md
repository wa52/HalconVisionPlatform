# 快捷匹配节点

节点类型 `halcon.quick-match`、版本 1，位于“定位匹配”。使用 HALCON 24.11 形状模板，不引入 AI。当前链路为：候选搜索 → 独立可靠性判定 → 可信位姿 → 位置矫正 → 固定 ROI 检测。

## 配置与操作

连接上游图像到 Image 输入，选中快捷匹配节点，点击 **绘制模板**。图像直接来自上游连线，界面没有模板文件路径参数，也不需要另选模板图片。无模板时点击单次/连续运行也会先接收上游图像，进入示教；这一轮不执行匹配，不把模板帧自匹配当作检测通过。

程序展开下方的 **模板绘制区**，临时隐藏运行日志。直接在图像上拖动矩形，松开完成，Esc取消；绘制结束恢复原面板布局。框选后再运行匹配。重新框选使用固定模板，旁边相机图标可从上游重新取帧，清除按钮仅清除范围。尚无有效当前帧时只执行必要上游子图；读取文件夹按序获取单帧，不默认读取第一张。修改上游配置后旧帧失效。

模板自动保存到项目所在目录的 `assets/templates/<项目ID>/<唯一ID>.png`，写入流程资源引用；保存项目后可恢复。每次重新示教产生独立快照，不覆盖旧模板或原图。模板范围在固定模板图上绘制，搜索范围在输入图上绘制。切换待检图片不会自动更换模板，避免每帧用自身建立模板后自匹配。旧项目中的 `templateImage` 保留为内部存储字段，基础和高级参数均不显示它。

模板图片不嵌入 `.hvproj`；内部资源字段保留绝对路径，移动项目根目录后需重新示教，本轮没有实现资源路径重定位。上游必须产出单帧 HImage；不把多图集合的第一张默认为当前帧。相机及任意上游处理链执行失败时，不回退使用旧图像。

基础区仅保留模板区域、搜索范围、最低接受评分及期望目标数量四项。绘制模板使用图标加文字，其他低频操作使用图标及1.5秒中文提示；高级匹配参数默认折叠。内部模板资源不再作为用户必填参数参与静态校验，执行器仍拒绝无效模板，不能输出假位姿。

| 参数 | 默认 / 范围 | 作用 |
| --- | --- | --- |
| 最低接受评分 | 0.6；(0,1] | 接受门槛；形状评分不是概率 |
| 期望目标数量 | 1；1–100 | 必须恰好满足的物理目标数；沿用存储键 maximumMatches |
| 候选搜索上限 | 5；2–1000 | 实际上限至少为期望数量+1；达到上限会保守拒绝 |
| 候选搜索最低评分 | 0.4；(0,1] | 实际取其与接受门槛的较小值，保留较弱竞争候选 |
| 允许位置范围 | 空为全图 | 只验证候选模型原点位置，不改变搜索 Domain |
| 竞争候选最小评分差 | 0.05；[0,1] | 阈值以下的近分竞争者也可能导致拒绝 |
| 重复候选位置 / 角度容差 | 2 px / 2° | 仅同时接近才去重；可根据模板尺度调整 |
| 起始角度 / 范围 | −180° / 360° | 起始 [-180,180]，范围 [0,360]，两者和不超过180°；搜索后再次检查 |
| 最大重叠 / 贪婪度 | 0.5 / 0.8 | HALCON 搜索设置；重叠抑制可能隐藏候选，贪婪度可能漏检 |
| 建模对比度 / 最小对比度 | 30 / 10 | 整数1–255 |
| 忽略整体明暗反转 | 否 | 可选 ignore_global_polarity |
| 单图搜索超时 | 5000 ms；1–60000 | 只约束 find_shape_model，不包括建模及全部原生调用 |

## 接受与拒绝规则

候选按评分和确定性坐标顺序处理。首先检查有限数值、图像范围、允许位置及角度；同位置且近角度的重复候选合并。合格目标数必须恰好等于期望值，有额外合格目标时不因第一名分数更高而放行。相同位置的不同方向不能视为两个实体。阈值以下但接近最后一个接受候选的竞争者也会触发歧义。

候选达到搜索上限时无法判断还有多少未返回候选，故拒绝。此机制只检查搜索返回的候选，不能证明被金字塔、MaxOverlap 或搜索启发式抑制的目标不存在；模板对称性诊断尚未实现。容差过大可能合并邻近物体，应在真实样本上验证。

| 状态 | 意义 |
| --- | --- |
| MATCH_OK | 本图通过配置的全部检查 |
| NOT_FOUND | 无候选、评分不足或目标数量不足 |
| AMBIGUOUS | 多目标、方向歧义、近分竞争或搜索上限饱和 |
| OUT_OF_RANGE | 有达到接受评分的候选越出位置/角度范围且合格目标不足 |
| TIMEOUT | HALCON 原生错误9400；本批次全部位姿清空 |
| MODEL_INVALID | 模板文件/建模失败；无可信位姿 |
| MATCH_REJECTED | 原始候选含无效坐标或评分 |
| MATCH_PARTIAL | 批量图像未全部通过；查看逐图原因 |

`status` 表示匹配质量；执行引擎 Success 只表示获得了结构化结果，不能作为放行信号。工作台匹配未通过时显示“执行完成 · 匹配未通过”，对应匹配结论为红色。位置矫正读取空的可信位姿后失败，后续固定 ROI 节点跳过，不会使用上轮坐标。

## 输出与坐标

保留 `matches/poses/imageResults/count/row/column/angle/score/preview/overlay/status/modelInfo`。`matches` 与 `poses` 只包含可信匹配，拒绝时为空，单图标量为 null；多图标量一直为空。`acceptedMatches` 是明确命名的单图可信输出，`rawCandidates` 仅诊断，不能连接位置矫正。每图结果包含原始候选、可信匹配、状态、拒绝原因及搜索/评估耗时；`timing` 包含模型获取、搜索、评估和总耗时，`modelInfo` 记录有效候选上限、门槛及模型身份。

一般拒绝仍可显示未画匹配轮廓的图像；仅可信位姿画绿色。模型无效或搜索超时不输出结果预览，且位姿清空。批量普通质量拒绝按每图保留接受结果；超时则整批不放行。原始候选无效数值不写入 JSON。

Row/Column 是模型原点在原图的行列坐标（默认模板区域重心），不是任意产品基准点。AngleDegrees 遵循 HALCON 旋转约定。搜索 Domain 约束建模区域重心位置；未来自定义原点不能直接等同于 Domain 的搜索基准。当前没有加入原点示教或更改变换约定。

## 兼容与生命周期

项目 schema、节点版本、既有端口及建模身份不变，缺少新参数时使用默认值；已有项目可直接加载和保存。安全语义更严格：旧 `maximumMatches` 现为期望的精确数量，不再仅为返回上限；旧 status 的 MATCH_FOUND/MATCH_NOT_FOUND 改为 MATCH_OK/NOT_FOUND，工作台仍识别旧结果显示。外部依赖状态字符串、最多数量行为或原始 matches 的集成必须适配，并重新验证现场项目。

模型缓存仍由工作区拥有、容量有界、独占租约串行访问，按模板内容 SHA256、路径、模板范围和建模参数识别。候选及接受参数变化不重建模型。获取失败也清除该节点旧缓存；搜索超时/异常/取消释放本轮模型。普通质量拒绝可复用有效模型。停止、项目切换和关闭清理模型，图像由执行结果拥有并释放。取消在算子边界及发布输出前检查，不承诺强制打断原生调用。
