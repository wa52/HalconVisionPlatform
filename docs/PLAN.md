## 1. 项目定位与边界

建设一套面向 Windows 工控机的 HALCON 工业视觉检测平台。工程师能够配置相机、建立产品检测方案、设置 ROI 和算法参数、调试检测流程；操作员能够选择产品、进入生产、观察判定、查看报警并追溯异常产品。

本项目独立建仓、独立解决方案、独立配置目录、独立安装包、独立版本发布。VisionInspection 只用于了解已有业务场景，不修改其代码、文档或运行配置，也不将新平台放进旧仓库。

第一版面向：单工位、单面阵相机、2D 传统视觉检测、一个确认的 PLC 协议。首个业务样板建议为扬声器零件的有无、数量、圆孔/外径/间距等检测，最终检测项由现场样品和公差确认。

平台目标是交付可配置、可测试、可维护的生产工具。HALCON 是算法引擎，平台还必须负责工程管理、调度、通信、日志、追溯和部署。

## 3. 技术选型与架构

推荐：Windows x64 + C# + WPF + MVVM + HALCON/.NET + HDevEngine。
.NET 已采用 .NET 8，并在本机 HALCON 24.11.1.1 x64 环境完成实际调用和 WPF 回归；其他环境仍需验证。
部署时锁定 HALCON、托管程序集、原生运行库、相机 SDK、操作系统和进程位数。

采用模块化单体桌面应用，第一版不引入微服务。检测数据本地处理；未来 MES 或 Web 统计通过单独接口扩展。

| 模块 | 职责 | 建议项目/目录 |
| --- | --- | --- |
| 操作界面 | 页面、命令、状态、权限入口；不编写检测算法 | HalconVision.App |
| 应用编排 | 生产状态、检测运行、方案发布、报警与追溯 | HalconVision.Application |
| 领域模型 | 方案、节点参数、结果、产品 ID、版本、坐标契约 | HalconVision.Domain |
| HALCON 适配 | 图像、区域、轮廓、模型句柄、算子和过程调用 | HalconVision.Halcon |
| 相机适配 | 文件回放、一个实际相机品牌的 SDK | HalconVision.Devices |
| 通信适配 | PLC 协议、握手、心跳、连接状态与输出 | HalconVision.Communication |
| 存储 | SQLite、方案文件、模型资源、结果图片、备份 | HalconVision.Persistence |
| 测试 | 纯逻辑、HALCON 集成、硬件、性能与异常注入 | tests |

依赖规则：Domain 不依赖 WPF 或 HALCON；Application 使用接口；HALCON/相机/通信为接口实现。UI 接收结果和显示快照，不持有正在检测的可变模型句柄。

### 算法接入的两条路径

1. 标准工具：通过 HALCON/.NET 封装定位、Blob、测量等固定能力，配套参数面板和测试。
2. 自定义过程：通过 HDevEngine 加载 HDevelop 过程，配置输入输出和参数；首先用于算法工程师扩展，V1 后期提供受控导入界面。

先以标准工具打通闭环，再增加自定义过程。HDevEngine 可以在 C# 等应用中执行 HDevelop 程序和过程；本项目用它实现算法逻辑独立维护。是否采用某项 API、是否支持特定 .NET 版本，须依据锁定版本实际验证。[S1]

自定义过程不是安全沙箱。只加载受信任、已审核和已回归的过程包，限定入口、输出格式、版本和模型目录。生产运行期间不允许修改已激活算法。

## 5. 图像、结果与方案契约

### 图像与资源

- HALCON 层内部使用适当的 HImage/HObject、区域和 XLD 表示；领域层不直接暴露这些句柄。
- ImageFrame 包含 FrameId、ProductId、相机 ID、帧号、像素格式、宽高、采集时间及缓冲生命周期。
- 从相机回调取得图像后，在 SDK 缓冲失效前复制或合法保留；第一版优先实现明确所有权的复制方案。
- 必测 Mono8、实际使用的 Bayer/RGB/BGR 格式、步长与通道顺序；不同格式不得靠猜测转换。
- 明确行列与 x/y、弧度与角度、像素与 mm 的转换边界。定位、ROI 跟随、显示和标定统一测试。
- 每个原生对象和模型句柄明确创建、拥有、共享与释放规则；异常路径同样释放。
- 模型和过程按内容哈希缓存；方案切换后，在在途检测结束且引用释放后再清理旧资源。

### 结果

InspectionResult 至少包含：
RunId、ProductId、FrameId、CameraId、RecipeId/Version、AlgorithmPackageVersion、
CalibrationVersion、开始/结束时间、节点指标、最终状态、错误码、图像路径和通信确认状态。

所有 HALCON 适配器将区域/轮廓转换成独立显示数据；不能将即将释放的原生对象交给 UI 使用。

### 方案

方案包由清单、参数、ROI、模型、过程、标定与版本元数据组成。禁止序列化进程句柄。
保存使用临时文件与原子替换；导入前验证 Schema、路径、资源哈希和算法能力。
存储位于明确可写的数据目录，例如 ProgramData 下的应用目录；安装目录不承载生产可变配置。
调试稿与生产发布版分开。生产以不可变快照运行，避免半轮检测使用两套参数。

## 6. 生产调度与错误处理

采集线程只接收、复制和入队；后台检测执行算法；UI 线程只更新显示；存储与通信分离但有明确完成条件。
单工位第一版一个检测执行通道，预览更新允许合并，生产检测帧不能静默丢弃。

状态覆盖 Idle、Ready、Busy、ResultPending、Error。离线调试不向真实设备发送结果。

1. 产品触发后分配关联 ID，登记待检产品与帧。
2. 检测结束按明确的 OK、NG、ERROR 枚举分支处理，未知状态进入 ERROR。
3. 结果和关联数据记录到本地，按现场协议发送并等待确认。
4. 确认或异常处理完成后才开放下一次握手；若现场允许流水生产，须另外实现序号关联协议。
5. 断线、采图失败、定位失败、缺必检结果、算法异常、结果过期均不得输出 OK。
6. 队列满时报告受影响的产品/帧并阻止继续放行；采取撤销 Ready、报警、停线或隔离的约定策略。
7. 通信重试必须沿用同一产品 ID/结果序号；接收端去重，不能因超时重试导致重复剔除。
8. Stop 后不接收新检测；在途结果按协议处理。重连后确认旧消息、设备状态和产品位置再恢复。
9. 磁盘满或结果写入失败时，按项目预先确认的追溯策略报警并阻止不满足追溯要求的产品放行。

单次 HALCON 调用不假设能被 CancellationToken 强制中断。先验证各算法超时能力；超时后即使后台返回结果也不得迟到放行。需要强制终止或故障隔离的场景，再引入独立算法工作进程。

软件承担检测判定与约定的设备握手；设备急停和安全联锁由现场控制系统实施。V0 确认本项目的控制边界。

## 8. 两个贯穿全程的样板方案

### A：装配有无与数量

工件图像 → 预处理 → 定位 → ROI 跟随 → Blob/存在检测 → 必检项规则 → OK/NG/ERROR → PLC 输出 → 原图和结果追溯。

覆盖：少件、多件、偏位、空图、定位失败、ROI 越界、相机断开、重复触发。
验收：工程师通过界面建立方案；操作员不改代码即可选产品和运行；异常不会当作合格品放行。

### B：尺寸与位置

标定 → 定位 → 直线/圆查找 → 外径/孔径/间距 → mm 公差判断 → 结果输出与追溯。

覆盖：公差上下界、测量目标缺失、角度变化、亮度变化、标定失效、重复测量。
验收：用确认精度的标准件对照，报告偏差与重复性；不以同一图片重复计算代替真实重复取像。

## 9. 验收标准与证据

下列数值为建议的试点门槛，M0 由现场确认后冻结。产品公差、图像质量和真实节拍不同，应形成书面调整记录。不能把这些目标当作 HALCON 的固有精度或性能。

| 维度 | 建议门槛 | 必须提交的证据 |
| --- | --- | --- |
| 功能闭环 | A/B 两套方案从创建到触发、输出、追溯均通过 | 操作录屏、方案包、固定样本结果和真机记录 |
| 缺陷判定 | 指定试点集上关键 NG 漏检为 0；良品误判率 ≤1% | NG 至少 300 个、OK 至少 500 个独立实物样本，按缺陷/批次列混淆矩阵 |
| 检测数据质量 | 调参集与最终验收集分离，覆盖多批次和边界样品 | 样本 ID、真实标签、批次、来源与评审记录 |
| 测量准确性 | 标准件最大绝对误差 ≤公差带宽的 10%，默认候选 | 参考值/参考量具不确定度、偏差、30 次真实重复取像报告 |
| 计量重复性 | 跨重装、日期和操作人员评估，按质量要求做 MSA | 重复性与再现性数据；不只报一张图片的稳定值 |
| 响应与吞吐 | p99 端到端时间 <现场允许期限；吞吐 ≥触发频率 | 预热后至少 10,000 次，含采图、排队、计算、持久化和通信确认 |
| 触发关联 | 额定负载下无未解释丢帧、错帧、重复结果和错误产品输出 | 触发/帧/检测/确认计数与产品 ID 对账 |
| 异常隔离 | ERROR/超时/无结果从不输出 OK；恢复不复用旧结果 | 故障注入用例、协议记录与报警记录 |
| 连续运行 | 8 小时初验、72 小时交付测试，无崩溃或错误放行 | 内存、句柄、延迟、队列、磁盘与异常趋势 |
| 资源稳定 | 预热后内存/句柄无持续增长；同负载最后一小时中位内存比首小时 ≤10% 增长 | 固定存图/缓存策略，趋势报告与增长解释 |
| 方案切换 | 100 次重复加载/切换无资源泄漏、参数串用或旧结果放行 | 版本、结果关联及资源监测记录 |
| 安装恢复 | 干净工控机安装成功；备份恢复后 A/B 方案正确运行 | 安装日志、恢复演练、兼容矩阵 |
| UI 操作 | 1920×1080、1366×768，100%/125% 缩放下核心操作可用 | 实际页面检查、操作员任务记录 |

300 个独立 NG 零漏检仅证明该验收样本上的表现；并不证明量产零漏检。零事件时的粗略单侧 95% 上限约为 3/N，300 个约 1%。更严格漏检率要求需要更多独立样本与持续量产监测。

性能指标必须记录工控机、版本、图像分辨率、算法参数、IO/通信方式和存图策略。未明确现场需求前，不宣称统一“100ms 内完成”。

## 10. 测试分层与责任

- 纯逻辑测试：方案校验、规则边界、状态机、产品关联、版本、队列策略和协议解析。不依赖 HALCON 或相机。
- HALCON 集成测试：在有合法授权的 Windows 测试机上验证图像转换、真实算子、模型读写、坐标和句柄释放。
- UI 检查：实际运行并完成创建方案、绘制 ROI、调参、切换产品、生产、报警、追溯任务。
- 硬件测试：真实相机、真实触发、真实 PLC 和输出接收端；模拟协议测试只能作为前置验证。
- 回归：固定样本集、错误样本集和既有功能任务随版本执行。

开发者负责实现与自检；算法工程师负责样品可检测性、光学/参数与误差解释；独立审核者负责功能/UI/回归/方案评审；现场质量和设备负责人确认生产验收。若资源只有一人，记录“独立审核尚未完成”，不能用开发者自评替代。

CI 区分无授权纯逻辑任务与有授权 Windows 集成任务。HALCON 缺失时，集成任务显示 BLOCKED/SKIPPED，不计为通过；发布必须附真实 HALCON 和硬件验收报告。

## 11. 持续开发 Loop

目标是持续推进到可交付和可商业化状态。每轮都有可验证的业务改善，允许根据真实反馈修订方案。

1. 重新评估平台：当前最影响现场价值的是准确性、配置体验、稳定性、维护还是缺少完整流程。
2. 研究与对标：结合官方 HALCON/HDevelop/HDevEngine 与 MERLIC 等成熟工具，按“建方案、调参、生产、诊断、追溯”比较具体任务；记录来源、日期和差距。
3. 制定轮次目标：定义触发场景、预期行为、UI 流程、成功门槛、依赖与证据，控制为可审查范围。
4. 执行与反馈：运行真实页面、图像或硬件；发现光学/算法路线不合适时提出依据并调整，不盲目堆工具。
5. 自检：运行适用的逻辑、算法、UI、回归和性能检查，整理可复现资料。
6. 独立审核：由未承担该轮实现的审核者检查功能、UI、回归、架构、错误放行风险与对标差距。
7. 失败修复：每个失败有 ID、复现步骤、证据、根因、修复和回归；连续两轮同类失败要重审设计。
8. 更新项目状态：记录实际进展、未完成项、现场阻塞及下一轮优先级。
9. GitHub 提交：提交独立仓库的代码和文档，记录 commit、验证环境和剩余问题。测试通过不自动等于阶段完成。

文档建议：
docs/PLAN.md、docs/ACCEPTANCE.md、docs/ARCHITECTURE.md、docs/COMPATIBILITY.md、
docs/BENCHMARK.md、docs/DECISIONS.md、docs/LOOP.md、docs/FAILURES.md、
docs/DEPLOYMENT.md、docs/OPERATOR_GUIDE.md。

每轮记录模板：
目标 / 现场场景 / 当前缺口 / 对标证据 / 方案 / 修改范围 /
验证结果 / 独立评审 / 失败与修复 / 剩余风险 / GitHub commit / 下一轮。

完成定义：功能可操作、现场效果达标、回归无退化、独立审核通过、文档与部署可用。
缺授权、缺设备、缺样品时暂停对应关卡并推进其他独立任务；不能制造验收证据。

## 12. 授权、成本与交付前提

HALCON 的开发授权与运行授权需分别确认，报价取决于版本/许可类型/数量与部署场景，官方不公布固定价格。[S2]
M0 取得正式报价并确认需要的算子/功能许可、开发机和部署工控机授权方式、离线使用、授权故障和迁移处理。
HALCON/.NET 和 HDevEngine 的应用集成不能被理解为免授权。
相机 SDK、HALCON 运行库与安装介质的分发方式遵循供应商条款；仓库不提交授权文件。

预算分开记录：开发授权、每台部署机运行授权、相机/镜头/光源/触发配件、工控机、现场调试和维护。
复杂反光/弱对比缺陷先验证成像；光学无法显示缺陷时，软件无法凭更复杂算法补足信息。

交付资料：安装包、版本清单、授权与环境指南、设备兼容清单、A/B 样板、标定记录、验收报告、用户手册、备份恢复与故障诊断说明。
量产试点追加：误判/漏判复核、模型/参数变更记录、返修原因和新样本纳入规则。

## 13. 首轮可直接执行的任务

首轮目标：在独立项目中验证 HALCON 技术路线和最小离线检测闭环。

1. 在已创建的 wa52/HalconVisionPlatform 独立仓库中建立解决方案，完善验收骨架。
2. 锁定一个 HALCON 版本，验证 Windows x64、候选 .NET 和 WPF 显示兼容。
3. 添加运行库/授权自检；缺授权时能浏览说明，但不能假装执行 HALCON 检测。
4. 加载一张真实样品图，正确显示尺寸、像素格式和坐标。
5. 绘制矩形 ROI，运行阈值 + 连通域 + 数量判定。
6. 展示数量、判定、耗时、区域叠加和失败原因。
7. 保存方案、原图和结果；关闭重开后复现。
8. 独立审核实际页面及正常/缺料/空图/坏图/缺授权用例。
9. 提交 GitHub 并记录已验证与待验证事项。

首轮不实现全部功能；它必须证明新项目实际使用 HALCON，且平台闭环可以持续扩展。
