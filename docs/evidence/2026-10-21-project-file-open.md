# 项目文件双击打开补充验收

日期：2026-10-21。本记录补充 [位置矫正首版记录](2026-10-19-position-correction.md) 中尚未确认的 Windows 双击行为。

## 检查方法与结果

从已有位置矫正检查项目复制出独立 `.hvproj` 副本，在 Windows 文件资源管理器中实际双击打开。以运行窗口的可访问性树和真实界面核对恢复内容，而不是只判断程序是否启动。

| 检查 | 实际观察 |
| --- | --- |
| 打开入口 | 文件资源管理器中的 `.hvproj` 双击 |
| 程序标题 | HalconVisionPlatform · 工业视觉检测平台 |
| 项目及流程名称 | 位置矫正检查 |
| 节点 | 读取图像、快捷匹配、位置矫正、二值化，共 4 个 |
| 连线 | 共 4 条，匹配位姿与原图分别连接矫正节点 |
| 启动路径 | 运行监控出现“已从项目文件打开：”及本轮检查副本的完整路径 |
| 原始文件保护 | 检查副本与来源文件哈希保持一致；没有保存覆盖原始项目 |
| 退出 | 正常关闭本轮平台实例与检查目录窗口，复核检查副本进程已退出 |

程序路径为本机既有 `artifacts/desktop-position-correction-checked/HalconVision.App.exe`；该目录的程序已由后续开发更新，不能把目录名称当作提交版本。本轮不替代快捷匹配、算法、生命周期或新版本发布验收，未重新执行检测推理。

本地可复核数据在 `artifacts/file-open-check-20261021/explorer-open-ui.json`：断言实际恢复 4 个节点、4 条连线及预期启动项目路径。该文件由实际运行窗口的可访问性树生成，不是仅从项目 JSON 推测界面状态。

## 后台 Shell 检查与真实双击的区别

本轮先执行了后台 `ProcessStartInfo.UseShellExecute=true` 打开同一检查副本，在 8 秒内未观察到携带该路径的平台进程，结果与 2026-10-19 的后台检查一致。直接给程序传入同一文件路径则成功，真实资源管理器双击也成功。

只读查询发现，扩展名和合并的 ProgID 注册命令均指向现有程序，项目参数包含引号；当前 Windows 的 `UserChoiceLatest/ProgId` 为 `Applications\HalconVision.App.exe`。未修改受保护的默认应用选择或其校验数据。

因此，**这次真实双击已通过**。后台 Shell 调用未观察到进程的具体原因尚未确定，不能继续将它当作用户双击失败的证据，也不能据此声称修复了一个程序启动缺陷。今后关联验收应包含真实资源管理器操作，以及项目名称、节点、连线和启动路径核对。

## 范围与限制

- 本轮为关联与项目恢复补充检查，未改动程序界面或算法；检查期间出现的其他代码修改保留，由其开发流程单独检查和发布。
- 实际运行界面受到其他应用通知干扰，未把含其他窗口内容的截图作为交付图片发布；本记录不宣称完成新的视觉设计验收。
- 使用一个既有单流程检查副本；多流程默认页、损坏项目、其他 Windows 账户/设备及推理结果不在本轮检查范围内。
