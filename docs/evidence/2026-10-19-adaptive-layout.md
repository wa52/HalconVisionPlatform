# 布局越界修复（2026-10-19）

## 复现

在实际 MainWindow 的 WPF 可视树上执行 Measure/Arrange，以 1180×680 的内容区布局。画布说明文字起点 x=410，宽度约 383，所属工具栏宽度仅 610，超出右边界约 183 像素。横向 StackPanel 与固定行高无法容纳新增图标及提示内容。

## 修复

- 工具栏使用 WrapPanel 和自动行高；菜单高度随内容调整。
- 顶部标题、项目名和运行按钮使用独立 Grid 列，长名称不挤占按钮空间。
- 图像标题与工具分行，运行日志限制在自己的列内；状态栏可换行。
- 移除画布内的固定说明角标；ROI 绘制提示改放图像上方。
- 左侧、属性区及下方面板分别保留最小操作尺寸；隐藏面板时同步取消最小尺寸，恢复时还原。
- 多个检测面板和内容区提供纵向滚动，图像区按分配空间布局。
- 独立图像窗口为标题、按钮和底部信息分配独立空间。

## 回归

```powershell
dotnet run --project tools/HalconLayoutCheck/HalconLayoutCheck.csproj -c Release
```

实测输出：

```text
布局检查数：72
PASS: 操作控件未超出所属区域
```

检查覆盖主窗口 1180、1366、1580 内容宽度、独立图像窗口 700 内容宽度，以及长名称。直接加载实际窗口布局，不执行模型推理、读取图像或连接相机；结束后释放测试窗口的图像控件与工作区资源。

该检查针对按钮与说明文字相对所属区域的几何边界，不代表所有屏幕 DPI、任意面板数量、检测标注或所有参数内容均已验收。
