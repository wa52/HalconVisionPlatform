# 多 ROI、分类与缓存验收 · 2026-10-16

## 环境与样本

Windows x64、.NET 8、HALCON 24.11.1.1 Progress-Steady，NVIDIA GeForce RTX 5060 Laptop GPU（8 GB）。读取本机 NH320 的 221×252 图像；分割模型 run_20261015_201455_3233ea79，分类模型 run_20261015_204851_6dfa373c。模型与训练数据未修改或上传，HALCON 安装及授权机制未修改。

测试创建独立项目和输出目录，未改动用户原方案。CLI 组合链路包含两个重叠启用 ROI 和一个禁用 ROI，覆盖反向绘制与部分越界。每个启用 ROI 又物理裁图后单独推理，用于差分检查。此方法验证裁剪执行一致性，不证明模型对产品的分类准确率。

## 性能与资源边界

无缓存首轮 77.68 秒，缓存版本首轮 90.18 秒，包含设备初始化和首次真实推理预热；缓存没有消除冷启动成本。无缓存后两轮均值 2418 ms；缓存后 99 轮均值 1269 ms，范围 1114–2031 ms，本机该样本下观察到约 47.5% 缩短。基线仅两轮稳定样本，非受控性能基准，不推广为其他模型/设备的保证。

缓存版本进程私有内存约 4.32–4.55 GB、工作集约 0.99–1.19 GB。第 21 到第 100 轮末值私有内存相差约 5 MB，中间有回落；每轮检查公开输出对象已释放，结束后模型条目清空。保留模型会提高内存和显存占用，默认容量为两个；尚未证明无长期增长。

本机 nvidia-smi 读取的是整卡总占用，包含其他进程与显示负载，未取得可独立归因的每进程显存曲线。不得把上述进程内存指标当作 GPU 显存，也不据此宣布显存长期无泄漏。取消在 HALCON 原生算子前后生效，17 ms 的传统算子停止记录不代表 DL 的最坏停止时延。

## WPF 交互发现与修复

真实鼠标绘制和 Ctrl+S 保存验证发现：ROI 数据正确但绘制后框消失。新增布局契约在修复前失败，原因是 Canvas 折叠后尺寸归零，恢复阶段提前返回；先恢复可见性再参与布局后契约通过，实际窗口松开鼠标后框和名称保持显示，放大时跟随变换。高级端口信息默认折叠，让 ROI 列表直接可见。

真实窗口先运行再进入检测模式发现底图黑屏。独立 WPF 回归复现“面板已 Loaded 但仍隐藏”的路径；可见性变化时调度刷新后通过。另补同位多条标注的覆盖检查，在修复前失败，增加文字避让后通过。这些 UI 契约使用独立窗口与真实 HALCON 图片，不涉及用户工程或系统 UI 设置。

真实 WPF 组合执行返回 Success：两个分割 ROI 合计 14 个区域、累计 7109 像素；四个分类 ROI 返回各自类别和置信度。重叠部分分别计数。准确率、完整 ROI 编辑交互矩阵、真实物理相机、长时间 CPU/GPU 稳定性及生产闭环仍需另行验收。

最终发布版再次通过两个 UI 契约。真实窗口重新执行两个分割 ROI 和两个分类 ROI 后再进入检测模式，底图、绿色目标轮廓及每 ROI 的标注同时正常显示；分类示例返回 NGP5 97.4% / 60.9%，仅记录模型输出，不作为正确标签。mask 端口提供“区域 A / 区域 B”两个独立选择并可切换。发布目录为 artifacts/desktop-dl-accepted，桌面快捷方式和 .hvproj 打开命令已核对指向该版本。旧窗口未强制关闭。
