# 自动归档与历史查询

入口：**项目 → 运行归档**。同一工作台只打开一个归档窗口，历史查看不改变当前检测结果或流程。

## 自动保存

1. 打开项目，在归档窗口选择文件夹，勾选“自动归档”。默认关闭，旧项目保持关闭。
2. 点击保存图标。该操作保存归档设置及当前所有流程到项目；运行期间不能更改。
3. 完整流程每轮完成后保存，包括失败、取消的完整流程结果；仅执行上游的示教调试不自动归档。归档使用执行时的配置快照，包含实际选中的文件路径。
4. 主窗口底部显示未启用、等待归档、已归档或归档失败。完整路径和错误可通过提示查看，日志保留本轮状态。
5. 保存失败保留本轮检测结果，连续运行停止并完成资源收尾，避免继续静默丢失归档。检测结论和归档成功是两个独立状态。

归档写入在后台完成，本轮执行在归档结束后才完成，因此不会积累无界写入队列，停止和关闭会等待本轮收尾。磁盘刷盘时间计入整体运行等待，不承诺磁盘故障时立即取消。没有自动删除、保留天数、磁盘配额或原图打包策略，请管理目录容量。

设置保存在项目的 `RunArchive` 字段中；绝对目录跨电脑迁移后应重新选择。旧版程序不支持本功能，可能忽略该字段，不应依赖旧版程序执行归档策略。

## 历史查看

无需打开项目即可选择目录查询。点击刷新图标，从第一页读取；按文件写入时间倒序，每页 50 个文件，不递归子目录。上一页/下一页翻页，“本页筛选”匹配项目、流程、历史结论及 RunId，仅过滤当前页，不是全库搜索。目录内容在翻页期间变化时请刷新重新查询。

每条记录检查版本、完整性及结果身份。损坏、无权限、读取预算超限等记录会显示为“读取错误”，不影响其余记录；选中可查看原因。有效记录显示项目、流程、完成时间、判定和 RunId，下方只读查看节点结果、错误、日志及执行时流程快照。查看历史不会替换当前项目、当前产品结论，也不会运行快照。

单条归档存储上限 64 MB；历史页为避免界面占用过多内存，单条读取预算 8 MB、每页合计 32 MB，超过预算显示原因并保留原文件。详情文本最多显示 100,000 字符，截断会提示，完整信息仍保存在文件里。

归档不打包原图、模型、许可证或程序二进制，文件中的路径不保证一直可用。不能仅凭这些记录独立重放检测，也没有完成硬件相机/PLC、长期运行或现场追溯验收。
