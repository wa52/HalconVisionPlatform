# 独立 ROI 检测任务与统一产品判定

Phase 1，2026-10-22 验收。工程师在“项目 → 检测任务”配置区域、任务和判定规则。检测模式只显示运行控制、图像及结果，不增加配置控件。

## 配置流程

1. 在画布连接图像来源与各算法分支。例如同一图像分别连接“二值化 → Blob”和“直线查找”。共享图像来源，算法节点分别属于各自任务。
2. 打开“检测任务”，在“检测区域”新增命名 ROI，选择图像来源。来源可以是原始采集图或位置矫正的输出，必须是任务分支之外的未标注单幅图像。
3. 选择“绘制任务区域”返回放大的图像区拖动矩形，松开保存、Esc 取消。无有效当前图时，仅运行来源及其依赖，不把这次上游预览当作完整检测。也可填写行列坐标。
4. 在“任务与规则”新增任务，绑定 ROI，选择已连接好的算法分支成员。一个 ROI 可关联多个任务；同一个可变算法节点不能被多个任务共用，需要复制分支。模型会话继续使用现有缓存。
5. 添加判定规则，下拉选择节点及输出端口，配置方式和字段。每个末端算法都需要规则。只有明确的规则满足，才形成合格结论。
6. 应用配置，使用项目保存写入 `.hvproj`。单次运行后，顶部显示产品 OK / NG / ERROR；配置窗口“本轮任务结果”提供逐任务原因。修改算法、ROI、规则或连接后，旧结论显示为待重新运行。

原有节点内 ROI 仍可用于普通流程。任务执行时用独立区域覆盖成员节点的 ROI，节点原参数不被改写。已配置任务的节点请在任务窗口调整区域，避免误认为节点自身 ROI 仍是实际运行范围。

## 区域与算法

区域使用图像原尺寸的像素行列坐标，首版为轴对齐矩形；不重新缩放或裁成另一个坐标系。位置矫正输出可作为共同基准，然后在基准空间定义固定区域。

支持二值化、Blob、直线查找、快捷匹配、分类、目标检测和语义分割。二值化限制 HALCON domain，Blob 限制输入区域；DL 节点用同一命名 ROI 裁剪推理，结果保持输入图像坐标。快捷匹配的任务区域只覆盖搜索范围，不修改模板范围。

任务执行前核对本轮帧、坐标空间、尺寸、单图和标注状态。越界区域不自动裁小；矫正后无效像素仍沿用有效区域防护。任务不接收另一任务的图像结果作为区域来源；共享的定位和位置矫正应放在任务分支之前。

检测显示配置仍可组合多个算法结果。在所绑定底图上选择任务成员的图形叠加，会同时显示对应任务区域及结论；同一 ROI 的多个任务合并标注。

## 规则

| 方式 | 输出及配置示例 |
| --- | --- |
| 数值范围 | Blob 的数量 `count`，下限和上限都为 1；闭区间 |
| 数值范围 | 分割的面积 `area`，按实际缺陷容许面积设置；0 可以是有效数值 |
| 文本相等 | 直线的状态 `status`，字段 `/Code`，期望 `FOUND` |
| 检测判定 | 分类/目标检测的 `decision`，字段 `/Code`；识别 OK、未检出、检出 NG |
| 匹配可信 | 快捷匹配的 `status`，字段 `/Code`；MATCH_OK 合格，NOT_FOUND 不合格，其他不可信状态为 ERROR |
| 布尔为真 | 后续明确输出布尔值的检测节点，不能用字符串代替布尔值 |

字段使用 JSON Pointer；整个数值端口留空，嵌套字段如 `/Code` 或 `/0/Confidence`。不执行脚本或表达式。缺端口、缺字段、null、错误类型、非有限数值及未知状态不能变成默认 OK。

## 产品判定

- **OK**：至少有一个启用的必检任务，所有必检任务的算法完成且全部规则合格。
- **NG**：正常完成可信检测，但必检任务的规则不满足。例如确定缺件、数量不符或检出 NG 类。
- **ERROR**：流程失败或取消、必检任务禁用/缺失、节点未完成、规则/数据无效、定位质量不可信或区域/帧不合法。
- **未配置**：旧方案或没有任务的普通算法流程，不能作为产品放行结论。

ERROR 优先于 NG。启用的可选任务若执行异常同样产生 ERROR；可选任务正常检测得到 NG 只保留其任务结论，不影响必检任务汇总。禁用的可选任务明确记录跳过。没有启用必检项时不允许 OK。执行状态 Success 仅表示算子流程完成，可能同时具有产品 NG 或 ERROR。

## 保存、复制和兼容

旧 schema 1 项目继续打开，且不会自动生成“全部合格”的任务。保存包含独立区域/任务的方案或导出流程时升级到 schema 2，旧程序会拒绝不支持的项目版本，防止忽略任务配置后继续运行。请先备份旧项目再切换生产版本。

区域来源、任务成员、规则来源和任务区域引用随流程复制/导入重映射。删除已引用节点会产生配置错误并阻止检测；不会静默移除对应必检条件。运行时图像、区域和模型句柄不写入方案，继续由工作区清理。

## 首版边界

复用一个流程 DAG 中独立的算法分支，依赖顺序串行执行；未引入嵌套子流程、并行任务线程、旋转/多边形区域、毫米标定、新测量算法、PLC 放行输出或生产追溯。本轮真实检查主要采用受控图像的 Blob 和直线任务，不能等同于各 DL 模型与真实物料的精度验收。

检查工具：`tools/InspectionDecisionTrial`（无 HALCON 依赖）和 `tools/HalconInspectionTaskTrial`（真实 HALCON、WPF 与资源检查）。详细记录见 [Phase 1 验收](evidence/2026-10-21-inspection-tasks.md)。
