# 快捷匹配、位置矫正与目标检测

适用于 HALCON 24.11、.NET 8 WPF。2026-10-21 验证的是已发布版本，未合入工作区中进行中的检测任务编辑改动。

## 接线与坐标

| 上游输出 | 下游输入 | 用途 |
| --- | --- | --- |
| 读取图像.image | 快捷匹配.image | 当前原图定位 |
| 读取图像.image | 位置矫正.image | 同帧、未标注原图 |
| 快捷匹配.poses | 位置矫正.poses | 仅使用被接受的位姿 |
| 位置矫正.image | 目标检测.image | 在固定基准空间内检测 |

快捷匹配的 `preview` 带轮廓，不能接入位置矫正原图输入。目标检测的 ROI 在**矫正后的图像**中绘制；检测模式底图也选择位置矫正的 `image`，叠加目标检测结果。当前版本不自动把下游框回投到未矫正原图。

## 使用顺序

1. 读取图像节点选择图片或文件夹，快捷匹配中使用“绘制模板”示教当前上游帧。
2. 位置矫正中设置基准。更换模板或图像来源配置后，按提示重新示教，不能复用失效身份。
3. 目标检测选择训练模型目录，必须包含对应的 `model.hdl`、`preprocess.hdict` 和清单元数据。
4. 在基准图中设置 P1～P6 六个 ROI。`expectedClass=$roi` 按每个 ROI 名称筛选类别；本次最低置信度0.5，每个 ROI 期望1个目标。
5. 单次运行，检查当前图像、各区域结果与数量。保存项目后，模型目录、ROI、基准和显示配置一并恢复。

本机可打开本轮保存的检查方案：`artifacts/aligned-detection-20261021/1111_定位检测验证.hvproj`。它保留用户1111的模板和基准，只在独立副本中补齐检测模型与第四条连线。没有覆盖桌面原方案。

该副本是**本机检查方案**：图片、模型及模板参数仍引用本机路径，不能作为可随意搬动的完整部署包。相对资源另有复制，不能据此宣称所有路径已便携化。

## 结果解释

- 绿色表示该 ROI 接受了符合类别、置信度和数量条件的结果。
- 红色表示该 ROI 未检出期望目标或数量异常；不能把未检出直接断言为现场缺料。
- 节点/流程 `Success` 只表示执行完成。实际截图中流程执行成功，但有4个红色区域，不能据此判产品合格。
- 匹配没有位姿时，位置矫正返回 `POSE_NOT_FOUND`，下游检测跳过且没有旧检测输出；恢复正常输入后可以继续运行。

模型 `run_20261020_182230_e5db1fd3` 仍标记 `bootstrap_unvalidated`。本轮验证接入、坐标和有限生命周期，独立真值、mAP、误接受及真实产线稳定性仍未验收。详见[实测记录](evidence/2026-10-21-aligned-detection.md)。

## 首张四处未检出的负样本核对

2026-10-22复查首张：P1/P4/P5/P6分别对应原分类目录 NGP1/NGP4/NGP5/NGP6 的 `0.jpg`；这些文件与当前模型训练导出的裁图SHA256完全一致，COCO中没有目标框。当前原图六个位置的裁图也与导出裁图做了像素差核对，P2/P3有框、四个NG位置无框，输出符合这份数据的标签约定。

因此这四个结果应解释为“没有接受普通目标”，不能直接计作漏检，也不意味着模型输出了NG类别。当前模型没有训练NG类别；红色未检出仍按必要普通目标缺失规则判断。

另张正常原图经过同一模板及基准，P1～P6均各接受1个目标。整图推理、降低阈值和扩大裁图范围未改善本次对照，所以保留现有ROI和0.5阈值。[样本核对及验证边界](evidence/2026-10-22-detection-negative-audit.md)。
