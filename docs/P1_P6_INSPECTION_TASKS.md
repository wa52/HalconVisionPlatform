## 流程及配置

读取图像 → 快捷匹配 → 位置矫正 → P1、P2、P3、P4、P5、P6 六个目标检测分支。

六个命名区域都引用位置矫正的 `image` 坐标空间。每个任务有自己的检测节点和规则；ROI 与任务分别保存。当前六分支复用同一个模型包；任务框架也支持为其他区域配置不同算法分支。

| 配置 | 本方案 |

| 区域名 | P1–P6，必须与期望类别一致 |
| 期望类别 | `$roi` |
| 最低置信度 | 0.5，各节点属性中独立设置 |

同一模型包、任务类型及设备使用一个独占模型会话，六节点和连续轮次共同复用；每次推理重新应用该节点的阈值。不同模型仍受缓存容量上限约束。见 [生命周期](DL_SESSION_LIFECYCLE.md)。

## 结果与边界

| 输入 | P1 | P2 | P3 | P4 | P5 | P6 | 产品 |
|---|---|---|---|---|---|---|---|
| 正常原图 | OK | OK | OK | OK | OK | OK | OK |
| 已核对负样本 | 未检出 | OK | OK | 未检出 | 未检出 | 未检出 | NG |
| 空白图 / 无可信定位 | 跳过 | 跳过 | 跳过 | 跳过 | 跳过 | 跳过 | ERROR |

异常、取消、缺结果或不可信定位不能成为产品 OK。`Success` 表示节点执行完成，产品是否合格看产品结论。P1 阈值设为 1 只使 P1 判为 NG，不污染其他节点。

当前模型标记 `bootstrap_unvalidated`，只含正常 P1–P6 类别。负样本 NG 来自“没有检出必需的正常目标”，不是检出专门 NG 类；本轮未验证蓝色 NG 类框。样本与训练标签有关联，本轮是链路联调和回归，不是独立精度验收。30 轮及有限 UI 循环不代替 8 小时和产线验收。
